# 圆桌讨论：Star 知识库图谱式视图设计

> 讨论时间：2026-07-17
> 讨论方式：soft_orchestration_only
> 讨论结构：standard，3 轮
> 焦点问题：star 知识库（500 个项目）的图谱式视图应如何设计？

## 参与角色

- **Mike Bostock** — D3.js 创作者，力导向图可视化专家
- **Tamara Munzner** — 信息可视化学者，《Visualization Analysis & Design》作者
- **Pieter Levels** — 独立开发者，MVP 落地视角
- **Brendan Gregg** — 数据可视化工程师，关注性能与可扩展性

## Round 1：节点和边如何定义？

**核心争议**：项目间互连 vs topic 为中心

- Mike Bostock：项目为节点，共享 topic 为边。但 500 节点全连是毛线球。
- Tamara Munzner：建议二部图——topic 做锚点大节点，项目做叶子小节点，项目归属到 topic。有参照物。
- Pieter Levels：不要项目间互连，只画 topic→项目。力导向自动聚类。
- Brendan Gregg：无 topics 的项目用 language 兜底聚类。

**结论**：二部图，topic 为引力中心，项目被吸引到所属 topic 附近。

## Round 2：技术选型

**候选**：D3.js / Cytoscape.js / ECharts graph / vis-network

- Mike Bostock：不推荐 D3（需手写大量交互，SVG 500 节点会卡）。推荐 Cytoscape.js。
- Brendan Gregg：Cytoscape.js canvas 渲染，500-2000 节点流畅。ECharts 图布局不如 Cytoscape 专业。
- Pieter Levels：Cytoscape.js 14k star，CDN 可直接引入，符合零构建原则。

**结论**：一致选择 Cytoscape.js。

## Round 3：交互设计 + 视图整合

- Pieter Levels：单页 tab 切换（卡片 / 图谱），共用过滤数据。
- Tamara Munzner：节点颜色=语言，大小=项目数（topic）/ star 数（项目）。悬停高亮关联，点击弹详情，点击 topic 过滤。
- Brendan Gregg：初始 cose 布局 animate:false，>200 节点关闭拖拽动画。
- Mike Bostock：边无箭头、透明度 0.3，图例放角落。

## 最终决策

| 决策项 | 结论 |
|--------|------|
| 节点定义 | 二部图：topic 节点（大）+ 项目节点（小） |
| 边定义 | topic → 项目（归属关系），无向，无箭头 |
| 聚类兜底 | 有 topics 用 topics；无 topics 用 language；都无则"其他" |
| 可视化库 | Cytoscape.js（CDN 引入，零构建） |
| 布局算法 | cose（力导向），初始 animate: false |
| 节点颜色 | 按语言分色（6 主色 + 灰色兜底） |
| 节点大小 | topic 节点 = 项目数量；项目节点 = 按 star 数微调 |
| 交互 | 悬停高亮关联、点击项目弹详情、点击 topic 过滤、双击重置 |
| 视图整合 | 单页 tab 切换（卡片 / 图谱），共用过滤数据 |
| 性能 | 500 节点 cose 布局 + canvas 渲染，>200 关闭拖拽动画 |
